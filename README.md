# Обжарка «Кварта» — Лендинг с формой заявки

## Стек
- **Frontend:** HTML5, CSS3, Vanilla JS (ES6+).
- **Backend:** PHP 8.4 (без фреймворков).
- **База данных:** SQLite (файл `app/storage/app.sqlite`).
- **Уведомления:** Telegram Bot API (cURL).

## Обоснование выбора архитектуры и БД
Выбрал **SQLite**, так как для лендинга с парой сотен заявок в день этого более чем достаточно. Это исключает необходимость поднимать отдельный сервер БД (MySQL), упрощает деплой на бесплатный хостинг и снижает TTFB. Файл базы защищен от прямого доступа через `.htaccess` и физически лежит вне веб-корня (`public/`).
Бэкенд на чистом PHP. Никаких фреймворков — минимальный оверхед, полный контроль над безопасностью (CSRF, rate-limit, идемпотентность) и скорость работы.

## Разделение обязанностей (Я vs ИИ)
- **Мной написано:** Архитектура проекта, настройка локального сервера, логика защиты от спама, обработка краевых случаев (откат UUID при ошибке Телеграма), маска телефона, верстка и адаптив.
- **ИИ сгенерировано:** Базовые заготовки для CSS-сетки, рутинный код для cURL-запросов в Telegram, структура классов PDO.
- **Кейсы, где ИИ ошибся (и как я исправил):**
  1. ИИ предложил делать проверку на дубли (Idempotency) *до* валидации полей. Из-за этого PHP падал с ошибкой `Undefined variable $phone`, так как номер еще не был очищен валидатором. Я переписал порядок middleware: сначала валидация, потом проверка дублей по номеру.
  2. ИИ поставил Rate Limit *после* проверки на дубли. Это позволяло спамить форму одним UUID, получая `200 OK` в обход лимита. Я поменял их местами и добавил принудительный откат UUID (`idempotency_release`) при любых ошибках, чтобы заявка не «застревала» в базе навсегда.

## Что не успел / Сделал бы иначе
- **Не успел:** Сделать админку для просмотра заявок из БД (сейчас они дублируются только в Telegram). Добавить более сложную капчу (сейчас honeypot + rate limit + проверка времени заполнения). В админке возможность редактировать текст, добавлять. удалять карточки, ставить бота. Базовое СЕО, набросать теги, сделать файлы для роботов и так далее. 
- **Сделал бы иначе:** Сделать более качественный CSS разбитый на модули и с говорящими классами как в [ моем другом проекте ]( https://github.com/blinkEgor/ViVaAuto_BCW ). Был бы клиент настоящим, то я бы с ним пообщался чтобы точно опредиться что ему нужно и сделал бы в точности по запросу с маленьким [ бонусом на подобии ]( https://github.com/blinkEgor/ViVaAuto_BCW/blob/main/js/clipboard.js ) что делал раньше и со свободными местами для будущего расширения.
